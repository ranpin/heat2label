heat2label

把模型内部的热力图变成伪 bounding-box 标注，让图像无需手画每个框就能（预）标注。两条独立的臂——同一思路的两种实现。

演示

预计算演示 · 两个模型都太重、无法在浏览器内运行 · 复现见仓库。切换 Grad-CAM++ / DAAM / 两臂对比 三个视图，选择划分与类别；每类两个示例并列展示，各走完整「热力图 → 伪框」管线。「两臂对比」把同一张 SD 生成图分别过两臂（自证 × 他证交叉验证）。

评测结果

两条臂是同一思路（热力图 → 伪框）的两种独立实现，下表对比各自的热力图来源、产出形态与适用域。

Grad-CAM++（cam2label）DAAM（daam2label）
热力图来源ImageNet 预训练 ResNet-101 上的 Grad-CAM++，预测驱动（targets=预测类）Stable Diffusion 交叉注意力（DAAM），文本 prompt 驱动
关键参数ResNet-101（torchvision IMAGENET1K_V1 权重）· 输入 224×224 · Grad-CAM++ 目标层 layer4[-1] · 热力图二值化阈值 170 · targets=预测类（top-1）CompVis/stable-diffusion-v1-4（fp16 + attention slicing）· 采样 30 步 · 生成 512×512 · guidance scale 7.5（diffusers 默认）· DAAM 逐词交叉注意力热力图
是否生成图像否——给已有图像打框是——SD v1.4 text2img 生成，再给输出打框
适用域COCO 零样本两划分的全部新类（65/15 的 15 类 + 48/17 的 17 类，每类 2 张真实图）+ dalle-mini 生成图组（仓库 2023 原始「生成→Grad-CAM→框」管道）与 Grad-CAM 臂相同的类别集（便于直接对比）+ 驾驶长尾附加（motorcyclist、truck）
框类型旋转框（cv2.minAreaRect）画在图上轴对齐 bbox → label.json（COCO 风格）
算力CPU 即可（实测 ~0.3s/图）建议 CUDA GPU ≥ 8GB（实测 ~4.7s/图）
入口gradcam/cam.py、gradcam/demo_assets.pydemo_daam.py（argparse CLI，--manifest 批量）

两臂不共享代码，是同一技巧的两种独立实现，并列保留以便对比；产出的每个框都是伪标注、仍需人工复核（定位是预标注 / 数据增强助手，非生产级标注器——与 2026 主流开集检测的实测对比与诚实定位详见仓库 README）。本表对比两臂的产出特征，非定量精度基准。顶部「两臂对比」视图把同一张 SD 生成图分别过两臂，呈现自证 × 他证交叉验证与 Grad-CAM 的 ImageNet 闭集词表限制。

核心方法

两条臂共享同一条管线，只在「热力图从哪来」和「服务什么域」上不同。

图像 ──► 模型前向 ──► 热力图 ──► 阈值化 ──► 区域 ──► 框
                │                                    │
       (Grad-CAM++ | SD 交叉注意力)        (轮廓 + minAreaRect | BFS 岛提取)
臂方法细节
Grad-CAM++ImageNet 预训练 ResNet-101 → Grad-CAM++ 类激活热力图（targets=预测类）→ 阈值化 → cv2.minAreaRect 拟合旋转框
DAAMSD v1.4 text2img 从简单 prompt 直接生成场景 → 逐词交叉注意力热力图（DAAM）→ 阈值化 + BFS 岛提取 → 目标类的轴对齐伪框 → 输出 COCO 风格 label.json
两臂对比同一张 SD 生成图 → DAAM 自证（prompt 关键词注意力）+ Grad-CAM++ 他证（ResNet 预测类），交叉验证生成质量
heat2label · 热力图 → 伪框标注（Grad-CAM++ + DAAM 两条臂，2023 研究 demo，MIT）
源码、模型与复现见 github.com/ranpin/heat2label
